# MTProxyL-Panel

Веб-панель управления прокси на движке **telemt** с поддержкой хостовых
возможностей **MTProxyL**: переключение режимов, Selfmask, лимитер, Zapret2,
блокировка стран, маршруты и бэкапы.

Один статический бинарник: фронтенд встроен в него, отдельный веб-сервер не
нужен. Интерфейс полностью на русском.

---

## Быстрая установка

Панель ставится **после** того, как поднят прокси — ей нужен работающий telemt
с доступным API.

### Из MTProxyL (рекомендуется)

```bash
mtproxyl panel install
```

Или через меню: `mtproxyl` → **Дополнения** → **Веб-панель MTProxyL-Panel**.

Интеграция с MTProxyL включится автоматически, права sudo будут выданы только
на нужные команды.

### Отдельно

```bash
curl -fsSL https://raw.githubusercontent.com/Liafanx/MTProxyL/main/mtproxyl-panel/install.sh -o install-panel.sh
sh install-panel.sh install
```

Установщик спросит логин и пароль администратора (пароль — дважды), а
остальное определит сам и покажет на подтверждение.

Если MTProxyL установлен, адрес API берётся из конфига движка **того режима,
который сейчас активен**: у менеджера это его собственный конфиг, у
реаниматора — конфиг чужой цели, и порт там свой. Заголовок авторизации,
если он задан в конфиге движка, подставляется тоже. Перед записью конфига
установщик проверяет, что API действительно отвечает.

В режиме Manager движок работает в Docker, поэтому про путь к бинарнику и
systemd-службу установщик не спрашивает — их там нет; вместо этого он
настраивает чтение логов из контейнера.

Панель выпускается отдельно от MTProxyL, её релизы помечены тегом
`mtproxyl-panel-vX.Y.Z`. Конкретную версию можно указать явно:

```bash
sh install-panel.sh install mtproxyl-panel-v1.0.0
```

### Сборка из ветки, без релиза

Пока релиз не выпущен (или чтобы проверить свежую ветку) панель собирается
прямо из исходников:

```bash
sh install-panel.sh install --from-source=dev
```

Если на сервере есть Docker — сборка пойдёт в нём, и тулчейн на сервере не
останется. Так же MTProxyL собирает сам движок telemt. Без Docker понадобятся
Go 1.25+ и Node.js 20+. В обоих случаях нужен `git`.

`mtproxyl panel install` предложит этот путь сам, если релиза не нашлось.

Порт установщик спрашивает, по умолчанию 8080 — после установки панель
доступна на `https://<адрес сервера>:8080`.

### Шифрование

Панель принимает пароль администратора и выдаёт токен сессии, поэтому
установщик спрашивает про TLS и по умолчанию предлагает включить его:

| Вариант | Когда подходит |
|---|---|
| Самоподписанный сертификат | по умолчанию: работает сразу, браузер предупредит один раз |
| Let's Encrypt | есть домен с A-записью на этот сервер |
| Свой сертификат | уже есть файлы .crt и .key |
| Без шифрования | только для доступа через localhost или туннель |

Самоподписанный сертификат панель создаёт сама при первом запуске и больше
не трогает: перезапуск его не меняет, так что предупреждение браузера
появится один раз. Без TLS cookie сессии не получает флаг `Secure` — об этом
панель пишет в журнал при старте.

Let's Encrypt на домене, для которого сертификат уже выпущен — обычно это
Selfmask на том же сервере, — панель не выпускает второй, а берёт готовый:
свой ACME ей тогда не нужен, порт 80 остаётся за nginx заглушки, продление
делает certbot. Тот же обмен работает и в обратную сторону: Selfmask,
настроенный после панели, передаёт ей свой сертификат сам.

### Управление

Через MTProxyL:

```bash
mtproxyl panel status      # состояние
mtproxyl panel restart     # перезапуск
mtproxyl panel uninstall   # удаление (спросит, оставить ли конфиг и данные)
```

Напрямую — панель ставится и без MTProxyL, поэтому и обычные операции с ней
не обязаны идти через его CLI:

```bash
sudo systemctl status mtproxyl-panel
sudo systemctl restart mtproxyl-panel
journalctl -u mtproxyl-panel -f
```

При удалении самого MTProxyL (`mtproxyl uninstall`) панель не удаляется
молча — установщик спросит про неё отдельно. Если её оставить, интеграция
отключается: снимаются права sudo на исчезающий скрипт MTProxyL и
выставляется `enabled = false`, после чего панель работает как обычная
панель telemt.

### Удаление без MTProxyL

Тем же `install.sh`, что и для установки — двумя эквивалентными способами:

```bash
# Уже скачан как install-panel.sh (см. "Отдельно" выше):
sudo sh install-panel.sh uninstall
sudo sh install-panel.sh purge

# Без сохранения на диск — сразу из пайпа:
curl -fsSL https://raw.githubusercontent.com/Liafanx/MTProxyL/main/mtproxyl-panel/install.sh | sudo sh -s -- uninstall
curl -fsSL https://raw.githubusercontent.com/Liafanx/MTProxyL/main/mtproxyl-panel/install.sh | sudo sh -s -- purge
```

`-s --` в пайпе обязателен именно в таком виде: без `-s` sh попытается
открыть `uninstall`/`purge` как путь к файлу скрипта, а не передаст их
установщику аргументом.

| | `uninstall` | `purge` |
|---|---|---|
| Служба и бинарник | удаляются | удаляются |
| Права sudo (`/etc/sudoers.d/mtproxyl-panel*`) | удаляются | удаляются |
| Конфиг (`/etc/mtproxyl-panel`) | остаётся | удаляется |
| Данные (`/var/lib/mtproxyl-panel`) | остаются | удаляются |
| Системный пользователь `mtproxyl-panel` | остаётся | удаляется |

Конфиг хранит логин и хеш пароля администратора — после `uninstall`
повторная установка находит его и пропускает мастер настройки, пароль
остаётся прежним. `purge` не оставляет ничего.

### Известные проблемы

**Ubuntu 26+: установка падает на `visudo: invalid sudoers file`.**

```
sudoers:15:37: syntax error: wildcards are not allowed in command arguments
mtproxyl-panel ALL=(root) NOPASSWD: /usr/bin/journalctl -u telemt -n * --no-pager -o short-iso
```

По умолчанию там `sudo` — это sudo-rs (переписанная на Rust реализация), и её
`visudo` пока не умеет символ `*` в аргументах команд — а часть правил
sudoers панели на нём держится (например, чтение диапазона строк лога).
Установщик покажет эту же подсказку прямо в момент ошибки. Лечится
переключением на классический sudo:

```bash
sudo update-alternatives --set sudo /usr/bin/sudo.ws
```

После этого установку можно повторить.

## Что умеет

### От telemt

| Раздел | Возможности |
|---|---|
| Дашборд | здоровье, аптайм, соединения, трафик, ошибки по классам; запуск, перезапуск и остановка движка при включённом мосте |
| Пользователи | создание, редактирование, удаление, квоты, ссылки `tg://`, накопленный трафик, история IP с GeoIP |

> **В режиме Manager пользователей ведёт MTProxyL, а не движок.** Его конфиг
> примонтирован в контейнер только для чтения, поэтому telemt не может
> записать пользователя и отвечает «Device or resource busy». Панель создаёт,
> правит и удаляет их через `mtproxyl secret`, а статистику по-прежнему берёт
> из API движка. Секрет при правке можно только перевыпустить — задать
> произвольный MTProxyL не умеет.
>
> По той же причине из панели нельзя сохранить конфиг движка: страница
> «Конфигурация» в этом режиме доступна только для просмотра. Порт, домен и
> маскировка меняются в «Настройках прокси», остальное — в «Экспертных
> параметрах» или в «Супер эксперте».
| Телеметрия | 11 разделов: гейты, пул ME, качество апстримов, NAT/STUN, самопроверка и др. |
| Безопасность | режим только чтения, белый список, заголовок авторизации, действующие лимиты |
| Конфигурация | форма быстрых настроек и полноценный редактор TOML |
| Логи | потоковый просмотр с фильтром и скачиванием |
| Обновление | обновление панели с проверкой контрольной суммы и откатом |

> **Накопленный трафик и история IP приходят не от движка.** Его списки
> «активные»/«недавние» живут только текущую сессию и пустеют при перезапуске
> цели или простое пользователя. MTProxyL копит и то и другое на диске и отдаёт
> по тому же имени пользователя, поэтому в карточке видно и сессионное
> состояние, и накопленное за всё время — в обоих режимах.
>
> Страна, город и провайдер появляются, только если установлена база GeoIP:
> раздел «Дополнения» или `mtproxyl geoip install`. Панель также подхватит
> базу, установленную системным пакетом, и заметит её без перезапуска.

### От MTProxyL

Появляются только при включённой интеграции.

| Раздел | Возможности |
|---|---|
| Режим работы | переключение Manager ⇄ Reanimator с выбором судьбы своего контейнера, состояние обнаруженной цели |
| Настройки прокси | порт, домен FakeTLS, маскировка, служебные порты — 16 настроек MTProxyL |
| Selfmask | домен, тип сертификата, шаблон сайта, применение, проверка, отключение |
| Трафик | накопленный трафик по пользователям в обе стороны, сортировка по любой колонке |
| Лимитер и защита | Zapret2 и Smart (By-MEKO) как взаимоисключающие способы, classic и iOS Fix v1/v2 — в устаревших, 25 параметров с валидацией |
| Блокировка стран | добавление и снятие блокировок по коду страны |
| Маршруты | исходящие маршруты MTProxyL: direct, SOCKS4/SOCKS5 (например WARP), Shadowsocks, веса и области (scopes) |
| Бэкапы | создание, восстановление, скачивание |
| Экспертные параметры | 189 параметров движка по секциям, поиск, сброс к сгенерированному |
| Супер эксперт | конфиг движка целиком в редакторе, включение и выключение режима |
| Дополнения | проверка домена на постквантовый обмен ключами, установка базы GeoIP |

## Как устроена интеграция

Движок telemt отдаёт REST API — оттуда берутся пользователи, статистика и
конфиг. Но переключение режимов, Selfmask и правила фаервола живут на уровне
хоста, и API их не покрывает. Для них панель вызывает CLI MTProxyL
(`internal/mtproxylctl`) и разбирает его вывод.

Панель работает под своим непривилегированным пользователем
`mtproxyl-panel`. Команды MTProxyL требуют root, поэтому установщик создаёт
`/etc/sudoers.d/mtproxyl-panel-mtproxyl` — **список конкретных разрешённых
команд**, а не право запускать `mtproxyl` целиком. Файл удаляется при
отключении интеграции и при удалении панели.

Значения, приходящие из браузера, проверяются дважды: панелью перед вызовом и
самим MTProxyL по его каталогу параметров.

### Параметры и применение — два разных шага

MTProxyL разделяет сохранение параметров и применение, панель это повторяет.
На страницах лимитера и Selfmask есть обе кнопки: **«Сохранить и применить»**
делает оба шага сразу, **«Только сохранить»** — откладывает применение.

Интерактивные мастера MTProxyL панель не запускает: под обходом подтверждений
они взяли бы свои значения по умолчанию и проигнорировали выбранное в
интерфейсе. Вместо них используются неинтерактивные команды — `nft set` +
`nft apply`, `selfmask set` + `selfmask apply`.

## Конфигурация

`/etc/mtproxyl-panel/config.toml`. Полный пример с комментариями —
[`config.example.toml`](config.example.toml).

Секция интеграции:

```toml
[mtproxyl]
enabled = true
script_path = "/opt/mtproxyl/mtproxyl.sh"
install_dir = "/opt/mtproxyl"
use_sudo = true
# command_timeout = "10m"
```

При `enabled = false` разделы MTProxyL скрываются, и панель работает как
обычная панель для telemt.

## Ограничения

- **Обновление telemt из панели недоступно при включённой интеграции.**
  Встроенный механизм рассчитан на telemt как systemd-сервис, а в режиме
  Manager MTProxyL держит движок в Docker. Обновляйте через `mtproxyl engine`.
- **Мастер Selfmask из панели не запускается.** Панель задаёт параметры
  (домен, тип сертификата, шаблон) и применяет их командой `selfmask apply`;
  интерактивный мастер `selfmask setup` остаётся только в CLI.
- **Одна операция за раз.** Переключение режима, установка Selfmask,
  восстановление бэкапа и применение правил не запускаются параллельно —
  они пишут в одни и те же файлы настроек.
- **Один администратор.** Ролей и двухфакторной аутентификации нет. Учитывайте,
  что переключение режима — root-действие на хосте, доступное владельцу сессии.
- **Только в режиме Manager** доступны бэкапы, маршруты, экспертные параметры и
  супер эксперт: все они опираются на владение конфигом движка, которого в
  режиме Reanimator нет. В интерфейсе они скрыты.
- **censorcheck не перенесён.** Проверка ограничений сервера запускает сторонний
  скрипт, скачанный из сети; такое по нажатию кнопки в вебе делать не стоит —
  команда осталась в меню MTProxyL.

## Сборка из исходников

```bash
cd mtproxyl-panel
make            # фронтенд + бинарник
make release    # сборки под x86_64 и aarch64 с контрольными суммами
```

Нужны Go 1.25+ и Node.js 20+.

Разработка:

```bash
make dev-frontend   # Vite с горячей перезагрузкой
make dev-backend    # go run с локальным config.toml
make hash-password  # хеш пароля для config.toml
```

Проверки, которые гоняет CI:

```bash
gofmt -l . && go vet ./... && go test ./...
cd frontend && npx tsc --noEmit
```
